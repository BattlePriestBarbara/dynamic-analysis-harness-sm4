# MB 客户端 Android 逆向与安全评估报告

> 一套**可复核、可复现、已脱敏**的移动客户端逆向工作记录。
> 对象：某全国性股份制银行的手机银行 Android 客户端（下文称 **MB 客户端**，`com.<vendor>.mobilebank.per`）。
> 仓库内只有文本报告与只读分析脚本，**不含样本二进制、不含抓包、不含密钥原文**。

---

## 0. 三十秒结论

这个客户端在外壳层面做得相当克制，在**运行时防护**层面做得相当激进：

1. **三层保护叠加**：iJiami（爱加密）DEX 加密 + native 代码自解密（SMC）+ 节头/符号表伪造 → 主 DEX 与关键 so 静态不可读；
   在此之上再叠 Bangcle Everisk 风控（528 类、明文、可完整反编译）与 PA / MicroDroid 支付沙箱（证书级接口鉴权 + 硬件虚拟化隔离）。
2. **静态面能拿到的已经拿全**：包结构、259 个组件、5 条深链、90 项权限、127 个 so 的能力栈、3 个加密容器的熵与魔数、
   `libexec.so` 的 539 个隐藏符号、业务路由表 151 个模块目录——这些都形成了**可复现的实测结论**。
3. **动态面：先撞墙，再发现墙是自己砌的**。用 unidbg 把壳的 native 完整跑起来之后，SM4 链路被逐跳还原
   （`setkey` → 轮密钥反转 → in-place 解密，约定判定 80/80 字节吻合），
   但取数环节长期被"索引命中失败"挡住。最后查明那不是壳的行为，而是
   **本仓库 harness 的兜底 hook 在索引构建中途把哈希表清零**：已插入的前 737 条被抹掉，
   剩下的条目恰好构成"局部头偏移 ≥ `0x511c9c4`"的假象。
   修复不到 10 行后索引恢复 5,161 条，目标资产被直接读到，SM4 链路第一次真正执行
   （[docs/08 §8.13](docs/08-APK内部索引缺口.md)）。
4. **这条弯路本身就是产物**：一个自洽、可复现、连数字都对得上的错误结论，
   是被"静态代码与运行时观测相矛盾"这一条线索推翻的——
   **优先怀疑仪器，其次才怀疑对方的设计**（[08 §8.13.7](docs/08-APK内部索引缺口.md) 归纳为四条教训）。

一句话：**保护的真实强度不在"加密有多难破"，而在"反调试 + 完整性校验 + 裸 syscall 退出"
把分析者挡在解密之前；一旦用仿真器绕过启动期校验，密码学部分反而很快见底。**

## 1. 合规与使用边界

- 本文档是对**已公开发布的商业客户端**的**互操作性 / 安全评估**记录，用于防护对抗、SDK 选型与甲方安全审计沟通。
- 仓库不含样本、不含可执行文件、不含可复用凭据（对称密钥仅留前 8 hex），不含任何绕过线上风控的可直接运行代码。
- 文中出现的第三方厂商名（iJiami、Bangcle Everisk、UnionPay、FinClip、mPaaS 等）均指**公开商业产品**，
  相关结论仅描述其公开可见的防护形态，不构成对其产品的评价。
- 若你是该应用的维护方并希望更正事实，请以 issue 形式指出**具体章节 + 具体测量值**，会按证据优先修正。

## 4. 这个仓库怎么提交

```bash
cd <WORK>/re-report
git init
git add -A
git commit -m "docs: MB client RE & security assessment (sanitized)"
git remote add origin <your-remote>
git push -u origin main
```

提交前**必须**先过一遍脱敏检查：

```powershell
# PowerShell 7
pwsh -File tools/check-sanitization.ps1

# Windows PowerShell 5.1（本仓库的原始开发环境）
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-sanitization.ps1
```

**0 命中才允许提交**。有命中时退出码为 1，脚本逐条给出 `文件:行号`、命中值、原因与原文；
`-Report` 只报告不失败，`-ListRules` 打印全部规则。

四条保证：

1. `.gitignore` 是**白名单模式**（`/*` 忽略一切，再放行 `docs/`、`tools/`、`README.md` 等），
   所以样本、APK、镜像、抓包即便被拷进本目录也不会入库；
2. `tools/check-sanitization.ps1` 会拦下三类：**形态**（Windows/UNC 绝对路径、用户目录、
   包名、域名、深链 scheme、证书主体）、**凭据**（16 字节密钥、40/64 位摘要、`key=…hex`）、
   **PII**（邮箱、手机号、IPv4、超长 base64）；
3. 真实身份词（厂商缩写、域名、库名、用户名）不在公开规则表里，而在
   `tools/scrub-map.local.psd1`——该文件被 `.gitignore` 拦截，**永不入库**。
   它缺失时脚本仍会跑形态检查，但会明确提示"身份字面量检查已跳过"；
4. `SANITIZATION.md` 记录了全部替换规则与已知取舍，便于第三方审计"这份报告到底脱了什么"。
