## 9.2 Deep Link（5 条，全部未 `autoVerify`）

| 组件 | scheme | host | 风险 |
|---|---|---|---|
| `...activity.SplashActivity` | `bankappgt://` | `wap.<vendor>.com.cn` | 未 `autoVerify` |
| `...activity.SplashActivity` | `bankapp://` | `wap.<vendor>.com.cn` | 未 `autoVerify` |
| `...activity.<Brand>PayActivity` | `bankappunion://` | `wap.<vendor>.com.cn` | 未 `autoVerify` |
| `AlipayResultActivity` | `alipay<vendor>://` | — | 未 `autoVerify` |
| `UrlRouterActivity` | 来自资源 `fin_applet_router_url_scheme` | — | 未 `autoVerify` |

**风险**：`autoVerify` 全关 → **任意应用可注册同名 scheme 抢占**；
`SplashActivity` 直接承载 `bankapp://` 跳转，是典型的**深链劫持 / 任意 URL 加载**审计入口。

- **待验证**：host 白名单是否在 `SplashActivity` 的入参处理里做严格校验（主 DEX 加密，静态不可读）。
- **修复建议**：为自有 scheme 开启 `autoVerify` + 发布 `assetlinks.json`；
  在入口处对 `host` / `path` 做**白名单**校验，拒绝跨域跳转；对 `UrlRouterActivity` 施加同样的约束。

## 9.3 权限（90 项，摘取高风险）

| 权限 | 风险说明 |
|---|---|
| `QUERY_ALL_PACKAGES` + `GET_INSTALLED_APPS` | 可枚举全部已安装应用（风控需要，但也是隐私面） |
| `REQUEST_INSTALL_PACKAGES` | 可触发 APK 安装（升级 / 插件） |
| `SYSTEM_ALERT_WINDOW` | 悬浮窗（覆盖攻击面，也可能用于安全键盘） |
| `READ_CONTACTS` | 通讯录 |
| `RECORD_AUDIO` + `MODIFY_AUDIO_SETTINGS` | 录音（语音助手 / 唤醒词） |
| `CAMERA` + `NFC` + `BIND_NFC_SERVICE` | 扫码 / 证件 / 手机公交卡 |
| 定位类 5 项 | 含已废弃别名 `ACCESS_GPS` |
| `READ/WRITE_EXTERNAL_STORAGE` + `requestLegacyExternalStorage=true` | 旧式外置存储 |
| `RECEIVE_BOOT_COMPLETED` / `DOWNLOAD_WITHOUT_NOTIFICATION` / `WRITE_SETTINGS` | 开机自启 / 静默下载 / 改系统设置 |

另有 **2 个非法权限名**（把常量当权限）：`MediaStore.Images.Media.INTERNAL_CONTENT_URI`、
`Manifest.permission.MANAGE_DOCUMENTS`。系统会忽略，无风险，但说明清单是代码拼出来的。

**修复建议**：按 targetSdk 收紧存储权限；把 `QUERY_ALL_PACKAGES` 收敛到 `<queries>` 白名单；
用 `SYSTEM_ALERT_WINDOW` 时给出用途说明并做运行时开关。

## 9.4 其他配置

| 项 | 实测 | 评价 |
|---|---|---|
| `allowBackup` | `false` | ✓ |
| `debuggable` | 未声明（=false） | ✓ |
| `usesCleartextTraffic` | `true` | ✗ 允许明文 |
| `networkSecurityConfig` | 仅 `base-config cleartextTrafficPermitted="true"`，**无 pin-set** | ✗ 弱 |
| 签名算法 | `SHA1withRSA` + **1024-bit** | ✗ 弱（应 ≥ 2048 + SHA-256） |
| 证书有效期 | 2010 → 2065 | 超长，且非 EV |
| 资源 | 全量改名（4,107 文件） | 提高分析成本，但造成 ARSC 引用不一致 |
| `.pa` 模板残留 | `implementation-class=com.example.demo.MyProvider` | 低（工程质量问题） |

## 9.5 风险排序（结合可达性）

| 级别 | 事项 | 依据 |
|---|---|---|
| **高** | 深链未 `autoVerify` + `SplashActivity` 承载 URL 跳转（劫持 / 任意加载，**待验证**） | §9.2 |
| **高** | 自有域内的 `gitlab.<vendor>.com` 等**内网资产泄漏**到客户端 | [02 §2.9](02-静态拆解.md) |
| **中** | 全局 `cleartextTrafficPermitted=true`，无声明式 pinning | §9.4 |
| **中** | `SYSTEM_ALERT_WINDOW` + `REQUEST_INSTALL_PACKAGES` 组合 | §9.3 |
| **中** | 1024-bit / SHA1 签名 | §9.4 |
| **低** | 内网 IP 硬编码（RFC1918）出现在资源中 | [02 §2.9](02-静态拆解.md) |
| **低** | 90 项权限中的冗余项；2 个非法权限名 | §9.3 |
| **低** | `.pa` 模板残留、ARSC 引用不一致 | §9.4 |

> **为什么"加固强度"不在表里**：加固解决的是"防逆向"，不解决"防劫持"。
> 本表列的是**产品自身可利用面**，加固水平是另一个维度（见 [02 §2.4](02-静态拆解.md)）。

## 9.6 值得肯定的部分

写风险报告时，把做对的地方也写清楚，结论才可信：

1. **`allowBackup=false` + 不声明 `debuggable`** —— 两个最常见的低级错误都没犯。
2. **主包单 ABI** —— 体积控制明确（虽然 `assets/` 里还是塞了 4 个 ABI 的风控库）。
3. **风控覆盖面真实**：Root / Hook / 模拟器 / 多开 / 无障碍 / 屏幕共享（含 RustDesk）/ 代理，
   且有 native 侧的 inline hook 检测与 ELF 符号解析，**不是"只查几个文件名"的摆设**。
4. **支付侧上了 PA / MicroDroid + 证书级 IPC 鉴权** —— 这个层级的隔离在同类产品中属于较高水位。
5. **密钥拆分存放**（配置一半 + 镜像一半），并用 `apkPath` 参与键名 —— 对重打包有真实阻力。
